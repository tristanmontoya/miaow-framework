Runtime orchestration¶

class SimulationUnit¶

Base class for model-specific simulation units.

The only requirement of a SimulationUnit is that it must implement an execute method that takes a Task and returns a caf::result<TaskResult>, which can be an immediate result, a CAF error, or a delegated response. The SimulationUnit class is intended to be subclassed by concrete implementations that define the specific behavior of the simulation unit.

Subclassed by miaow::DynamicBmiSimulationUnit, miaow::StaticBmiSimulationUnit< BmiModelType >

class JobController¶

Per-job policy for generating tasks from completed task records.

One controller instance belongs to each submitted job and remains in the parent process that owns Runtime. Only the owning job actor calls generate_new_tasks(). Calls are serialized even when multiple workers finish concurrently, so controller members accessed only by this method do not require a mutex. Results from workers that finish concurrently may be processed in either order.

generate_new_tasks() runs synchronously and should return promptly. Long-running or blocking work delays queued task results, shutdown requests, and the job timeout.

Tasks returned by one call are appended to the job in vector order. The first returned task receives the next available TaskId, and the remaining tasks receive consecutive TaskId values. Before dispatch, returned tasks undergo the same runtime-field assignment and duplicate-name validation as initial tasks.

int miaow::run_subprocess_worker(int argc, char *argv[], std::function<TaskResult(const Task&)> task_handler)¶

Run a subprocess worker that handles serialized tasks from its parent.

Every executable registered with SimulationUnitRegistry::add_subprocess() must call this function once from its main() and pass the supplied argc and argv unchanged. The handler runs serially for each received Task, and a persistent subprocess may invoke the same handler more than once. An exception from the handler produces a failed TaskResult.

Parameters:

  • argc – Command-line argument count supplied to the subprocess executable.

  • argv – Command-line arguments supplied to the subprocess executable.

  • task_handler – Callable that executes one received Task and returns its TaskResult.

Returns:

Zero after orderly worker shutdown or one after setup failure.

JobHandle submit_job(std::vector<Task> tasks) const¶

Submit multiple tasks and return immediately with a JobHandle.

Call JobHandle::get() to wait for the tasks to finish and obtain their JobRecord.

Passing an already-created task vector copies the vector and its tasks, leaving the original unchanged. Passing a temporary task vector, such as the return value of a function call, or using std::move allows MIAOW to reuse the vector’s existing storage and tasks instead of copying them. Do not rely on the contents of an explicitly moved vector afterward.

The returned handle may throw if job execution or final job_record.json output fails.

Parameters:

tasks – Tasks to submit.

Throws:

std::filesystem::filesystem_error – if runtime output directories cannot be created.

Returns:

JobHandle used to wait for and retrieve the resulting JobRecord.

JobHandle submit_job(std::vector<Task> tasks, std::unique_ptr<JobController> job_controller) const¶

Submit tasks with a controller that may generate additional work.

The runtime takes ownership of job_controller. After each task execution returns success or failure, the owning job actor creates its TaskRecord, passes all completed task records to the controller, and appends any returned tasks to the job. An empty tasks vector returns an empty JobRecord without invoking job_controller.

If the controller or preparation of its returned tasks fails, the job stops dispatching pending tasks and allows active tasks to finish. The returned handle then throws std::runtime_error. No final JobRecord or job_record.json is produced for this job-level error. Output failures may also be rethrown by the handle.

Parameters:

  • tasks – Initial tasks to submit.

  • job_controller – Controller transferred to the submitted job.

Throws:

  • std::invalid_argument – if job_controller is null.

  • std::filesystem::filesystem_error – if runtime output directories cannot be created.

Returns:

JobHandle used to wait for and retrieve the resulting JobRecord.

class PartitionedBmiRealization¶

NextGen-style realization expanded into BMI tasks by feature.

The constructor reads a NextGen-style global realization with one bmi_fortran module and CsvPerFeature forcing, resolves relative paths and expands sibling catchments.geojson features. One Task is built for each feature (e.g., catchment or response unit) with a sequential pipeline containing the BMI model and its associated forcing. The tasks can be executed concurrently by a DynamicBmiSimulationUnit.
