Examples¶

Examples are opt-in workflows that demonstrate MIAOW features and model integrations. Select and build them through the repository build as described in Building examples, then run them from their own examples/<example_name> directories:

cd examples/00_hello
./miaow_hello
cd ../01_heat
./miaow_heat
cd ../02_soil_freeze_thaw
./miaow_soil_freeze_thaw --output_root ./output --max_workers 2
cd ../03_dynamic_bmi
./miaow_dynamic_bmi --output_root ./output --max_workers 2
cd ../07_job_controller
./miaow_job_controller

Default examples¶

  • examples/00_hello: minimal orchestration and diagnostics output

  • examples/01_heat: BMI integration using the CSDMS heat example

  • examples/02_soil_freeze_thaw: static SoilFreezeThaw BMI integration with aligned per-task forcing

  • examples/03_dynamic_bmi: in-process dynamic C++ and Fortran BMI plugin integration using the CSDMS heat examples

  • examples/07_job_controller: computes a square root using Heron’s method, where tasks output the next estimate and residual for the job controller to check for convergence and generate the next task

Additional examples¶

  • examples/04_summa: SUMMA run using subprocess pipeline execution and one MIAOW task per staged catchment feature described by a NextGen-style realization

  • examples/05_libtrixi_bmi: Trixi.jl workflow using the libtrixi dynamic BMI plugin in a single-task subprocess

  • examples/06_fuse_bmi: deterministic 256-member Saltelli ensemble using the FUSE dynamic Fortran BMI plugin

SUMMA¶

The examples/04_summa example builds a SUMMA BMI library from a SUMMA source tree and runs the packaged gauge realization by default. It is not part of the default example set. SUMMA requires NetCDF C/Fortran and BLAS/LAPACK support. Select it with MIAOW_EXAMPLES=04_summa, then run it from the example directory:

cd examples/04_summa
./miaow_summa --output_root ./output

The following example-specific flags control the SUMMA build:

Flag

Default

Description

-DMIAOW_SUMMA_MODEL_ROOT

${MIAOW_DEFAULT_MODEL_BASE_DIR}/summa

Local or fetched SUMMA source tree

-DMIAOW_SUMMA_LIBRARY_LINKS

-framework Accelerate on macOS, empty otherwise

LAPACK/BLAS link flags passed to SUMMA

Trixi.jl¶

The examples/05_libtrixi_bmi example runs Trixi.jl configs through MIAOW’s libtrixi dynamic BMI plugin path. It is not part of the default example set, so it should be selected using MIAOW_EXAMPLES=05_libtrixi_bmi. The following example-specific flags control the libtrixi paths:

Flag

Default

Description

-DMIAOW_LIBTRIXI_BMI_ROOT

${MIAOW_DEFAULT_MODEL_BASE_DIR}/libtrixi-bmi

Local or fetched libtrixi-bmi checkout

-DLIBTRIXI_INSTALL_DIR

<libtrixi-bmi>/build/libtrixi-install

libtrixi installation root

-DLIBTRIXI_PROJECT_DIR

<libtrixi-bmi>/build/libtrixi-julia

Julia project directory

-DLIBTRIXI_DEPOT_PATH

<libtrixi-bmi>/build/julia-depot

Optional Julia depot passed to trixi_initialize

Trixi.jl and libtrixi are distributed under the MIT License.

FUSE¶

The examples/06_fuse_bmi example runs a deterministic 256-member Saltelli ensemble through FUSE’s dynamic Fortran BMI plugin. It requires NetCDF Fortran and Python 3 with no additional packages. The NetCDF parameter files are tracked in examples/06_fuse_bmi/data/paramsets, while CMake locates or downloads the forcing, elevation-band, and settings data. This case is not part of the default example set.

Using six workers, the ensemble can be run from the example root directory with the following commands:

cmake -S . -B build \
    -DBUILD_EXAMPLES=ON \
    -DMIAOW_EXAMPLES=06_fuse_bmi \
    -DMIAOW_FUSE_FETCH_DATA=ON
cmake --build build --target miaow_fuse_bmi
cd examples/06_fuse_bmi
./miaow_fuse_bmi --max_workers 6 --task_request_timeout 900 --job_request_timeout 14400

The following example-specific flags control the FUSE model and data paths:

Flag

Default

Description

-DMIAOW_FUSE_MODEL_ROOT

${MIAOW_DEFAULT_MODEL_BASE_DIR}/fuse

Local FUSE checkout; CMake fetches the pinned revision when it is absent

-DMIAOW_FUSE_DATA_ROOT

Empty

Extracted fuse_grid dataset; CMake first checks ${MIAOW_DEFAULT_MODEL_BASE_DIR}/fuse_grid when this is empty

-DMIAOW_FUSE_FETCH_DATA

OFF

Download the verified FUSE grid archive when no local dataset is available

The opt-in download uses the FUSE grid test case. CMake stores the extracted dataset and generated task configurations under build/fuse_grid_data, which is ignored by Git. The provided parameter sets were generated using FUSE’s bmi/generate_param_sets.py script at revision d73d24bb8678908973ca6f82f9d6eb6405cbb85f with N_BASE_SAMPLES = 8 and CONSTRAINTS_FILE set to the settings/fuse_zConstraints_snow.txt file from the downloaded fuse_grid dataset. The script creates 256 parameter sets in NetCDF format, which are tracked in this repository under examples/06_fuse_bmi/data/paramsets.

The FUSE repository is distributed under the GNU General Public License version 3.

Example command-line options¶

Examples use the following runtime command-line options where applicable:

Option

Default

Description

--max_workers

1

Maximum number of worker actors used for each job

--task_request_timeout

5

Timeout for one task execution, in seconds; MIAOW terminates the child process when a subprocess task exceeds this timeout

--job_request_timeout

300

Maximum runtime for one job, in seconds

--output_root

""

Root directory path for runtime-managed output folders, disabled by default

Public CLI parsers throw std::runtime_error for unrecognized arguments, missing option values, and invalid option values. Example executables catch these errors, print the message, and exit with status 1.
